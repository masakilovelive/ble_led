Differences From ORIGINAL_SEQUENCE.mmd
-------------------------------------

1. Diagram type changed.
- ORIGINAL_SEQUENCE.mmd is a `flowchart TB`.
- This file is a `sequenceDiagram` focused on runtime message order.

2. Main controller changed.
- Original content was centered on Android / Flutter app flow.
- Current implementation is centered on Python GUI `gui_c3_state_check_dual.py`.

3. MCU runner was added.
- Original endurance flow was app-side `Scan -> Connect -> GATT/Battery -> Disconnect`.
- Current code adds `MCU Power Runner (UNO)` and keeps `PC BLE Control` as another mode.

4. Serial control path was added.
- The GUI now sends `set off`, `set ab`, `set bs`, `set cw`, `set dw`, `set son`, `set sof`, `set stopfail`, and `run` / `stop` to UNO.
- This path did not exist in the original diagram.

5. Endurance timing ownership moved.
- Original chart assumed the app owned the full cycle timing.
- In MCU mode, UNO owns power timing and exposes windows with `[STATE] CONNECT_WINDOW_BEGIN/END` and `[STATE] DISCONNECT_WINDOW_BEGIN/END`.

6. Power control stages were made explicit.
- Current flow has `POWER_A_ON`, `POWER_B_ON`, and power-off staging driven by UNO.
- Original chart did not model A/B staged power sequencing.

7. Sensor checkpoints were added.
- Current UNO flow checks sensor-on and sensor-off checkpoints and emits `SENSOR_ON_OK/NG` and `SENSOR_OFF_OK/NG`.
- These checkpoints and their failure handling were absent from the original chart.

8. Failure classes were extended.
- Current implementation classifies MCU-related failures such as `SENSOR_ON_MISMATCH`, `SENSOR_OFF_MISMATCH`, and `MCU_COMMAND_TIMEOUT`.
- Original chart only described generic PASS/FAIL style endurance classification.

9. Target scope changed in MCU mode.
- Original chart described both stocks from the app perspective.
- Current MCU mode runs only the selected pair from the GUI's `MCU Pair` selector.

10. Logging and output location changed.
- Original chart referenced Android-side flow and `Documents/endurance_reports`.
- Current Python GUI writes `sequence_events_*.csv`, `endurance_report_*.csv`, and `endurance_report_summary_*.csv` under the local `logs` directory.

11. Baseline validation is stricter in the current flow.
- Current GUI explicitly validates register baseline and records `REGISTER_BASELINE_OK / REGISTER_PAIR` before endurance start.
- Original chart mentioned setup/save flow, but not this Python-side pre-run gate in detail.

12. The original chart is now incomplete for current behavior.
- It does not show UNO serial state events.
- It does not show dual runner mode.
- It does not show MCU-driven connect/disconnect windows.
- It does not show sensor checkpoint failures.

Recommended interpretation
--------------------------

- Keep `ORIGINAL_SEQUENCE.mmd` as a historical high-level app flow.
- Use this file when documenting the current MCU-integrated endurance path in `gui_c3_state_check_dual.py`.
